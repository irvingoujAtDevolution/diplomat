DiplomatStr — a layered walkthrough

Tracing one string from a C# string down to a Rust &[u8] and back. The example below crosses five layers; each layer is the auto-translation of the one above it, and the binary contract sits in the middle.
user code C# idiomatic (auto-gen) C# raw P/Invoke (auto-gen) C ABI contract (binary) Rust shim (macro-gen)

The example

We add one method to Color that counts how many UTF-8 bytes its name has. We pick this shape on purpose:

  • one slice param, one primitive return — pure focus on the slice mechanics
  • no Option, no Box — those are different codegen problems
  • the test value "héllo" is 5 chars but 6 UTF-8 bytes — the boundary translation is visible

Layer 1 — Rust source (what the dev writes)

dotnet_smoke/src/lib.rs rust source 
#[diplomat::bridge]
pub mod ffi {
    use diplomat_runtime::DiplomatStr;

    #[diplomat::opaque]
    pub struct Color { pub brightness: u8 }

    impl Color {
        pub fn name_length(name: &DiplomatStr) -> u32 {
            name.len() as u32
        }
    }
}
Why &DiplomatStr and not &str?
DiplomatStr = [u8] (a literal type alias in diplomat_runtime). It is unvalidated UTF-8. You can also write &str and Diplomat accepts it, but the HIR collapses both into the same node (Slice::Str(_, Utf8)) because once you cross FFI, "checked UTF-8" is only a convention. &DiplomatStr is the honest spelling.

Layer 2 — Macro-expanded extern (what diplomat::bridge emits)

The #[diplomat::bridge] macro reads your source and, for each method, emits an extern "C" shim with every Rust-flavoured type rewritten into something repr-stable.

generated by the macro (you never write this) rust shim 
#[no_mangle]
pub unsafe extern "C" fn Color_name_length(
    name: diplomat_runtime::DiplomatStrSlice,  // <-- &DiplomatStr became this
) -> u32 {
    let name: &[u8] = name.into();             // From<DiplomatSlice> for &[u8]
    Color::name_length(name)
}

DiplomatStrSlice is just an alias defined in runtime/src/slices.rs:

runtime/src/slices.rs runtime 
pub type DiplomatStrSlice<'a> = DiplomatSlice<'a, u8>;

#[repr(C)]
pub struct DiplomatSlice<'a, T> {
    ptr: *const T,
    len: usize,
    phantom: PhantomData<&'a [T]>,
}
Key takeaway. The Rust signature fn(&DiplomatStr) -> u32 has been mechanically rewritten into fn(DiplomatSlice<u8>) -> u32. That is the actual function that the OS loader sees in the .dll's export table.

Layer 3 — The C ABI contract (the binary truth)

This layer has no source code in either language. It's the binary agreement both sides have to honour. For our method:

Color_name_length — exported symbol C ABI 
// In C terms, the export looks like:
struct DiplomatSliceU8 {
    const uint8_t* ptr;   //  8 bytes on x64
    size_t         len;   //  8 bytes on x64
};                        // 16 bytes total, passed by value

uint32_t Color_name_length(struct DiplomatSliceU8 name);
Two-word fat pointer, by value. Every borrowed slice in Diplomat — string or primitive, &[T] or &mut [T] — boils down to { T*, usize } at the ABI level. The "mut" is a Rust-side invariant; ABI-wise it's just *mut T vs *const T.

Layer 4 — C# raw P/Invoke (what our codegen will emit)

The .NET backend mirrors the ABI struct exactly with [StructLayout(Sequential)], then declares the extern with that struct as the param type. This is the "raw" layer — direct, unsafe, one-to-one with the ABI.

dotnet_smoke/out/Raw/DiplomatSliceU8.cs (codegen) C# raw 
namespace DotnetSmoke.Raw;

[StructLayout(LayoutKind.Sequential)]
internal unsafe struct DiplomatSliceU8
{
    public byte* Ptr;   // matches *const u8
    public nuint Len;   // matches usize (nuint = native-sized uint)
}
dotnet_smoke/out/Raw/Color.cs (codegen) C# raw 
namespace DotnetSmoke.Raw;

internal static unsafe partial class Color
{
    [DllImport("dotnet_smoke", CallingConvention = CallingConvention.Cdecl,
               EntryPoint = "Color_name_length")]
    public static extern uint NameLength(DiplomatSliceU8 name);
}
Why nuint? Rust's usize is "pointer-sized" — 4 bytes on x86, 8 on x64. .NET's nuint is the same: a native-sized unsigned integer. Using uint here would silently truncate on 64-bit systems for any slice larger than 4 GiB.

Layer 5 — C# idiomatic wrapper (what the user actually calls)

The user shouldn't have to think about fat pointers, encoding, or pinning. The idiomatic layer takes a regular string, encodes it to UTF-8, pins the byte array so the GC can't move it, and constructs the raw struct.

dotnet_smoke/out/Color.cs (codegen) C# idiomatic 
namespace DotnetSmoke;

public sealed partial class Color : IDisposable
{
    public static uint NameLength(string name)
    {
        unsafe
        {
            byte[] nameBytes = Encoding.UTF8.GetBytes(name);
            fixed (byte* namePtr = nameBytes)
            {
                return Raw.Color.NameLength(new Raw.DiplomatSliceU8
                {
                    Ptr = namePtr,
                    Len = (nuint)nameBytes.Length,
                });
            }
        }
    }
}
The fixed block is load-bearing. Inside fixed, the GC promises not to move nameBytes, so namePtr stays valid. Outside the block, the pointer is dangling. This is why Rust must not retain the slice past the call — and why Diplomat's HIR rejects any signature that would let it.

Layer 6 — User call site

dotnet_smoke/tests/Program.cs user code 
uint len = Color.NameLength("héllo");
// len == 6     (NOT 5 — "é" is two UTF-8 bytes)

End-to-end data flow for "héllo"

1. User code (C#)
Color.NameLength("héllo") — a managed .NET string, stored as UTF-16 internally: [0x0068, 0x00E9, 0x006C, 0x006C, 0x006F] — 5 code units, 10 bytes.
↓
2. Idiomatic wrapper encodes
Encoding.UTF8.GetBytes("héllo") allocates a managed byte[6] on the heap with the bytes shown below.
↓
3. fixed block pins the array
The GC marks the array as immovable. namePtr now points to its first byte, with a guaranteed-valid lifetime for the duration of the enclosing fixed block.
↓
4. Build raw fat pointer
new Raw.DiplomatSliceU8 { Ptr = namePtr, Len = 6 } — a 16-byte struct, passed by value on the stack.
↓
5. P/Invoke crosses the boundary
The CLR marshals nothing — the struct is blittable, so it's a raw memcpy onto the native stack. Control transfers to Color_name_length in dotnet_smoke.dll.
↓
6. Rust shim rehydrates the slice
name.into() calls From<DiplomatSlice<u8>> for &[u8] which does slice::from_raw_parts(ptr, len). name is now a bonafide &[u8] pointing into the C# heap.
↓
7. User Rust runs
name.len() as u32 → 6u32.
↓
8. Return value crosses back
A 4-byte uint32_t in eax — standard C ABI primitive return. CLR sees a uint.
↓
9. fixed block ends, GC takes over again
namePtr is now invalid. nameBytes can be collected at the next GC cycle. The boundary is closed.

What's actually in memory

The C# string (UTF-16, 10 bytes)

charhéllo
UTF-16 code unit 0x00680x00E90x006C0x006C0x006F
bytes (LE) 68 00E9 006C 006C 006F 00

After Encoding.UTF8.GetBytes(...) (UTF-8, 6 bytes)

byte index012345
hex 68 C3 A9 6C 6C 6F
meaning 'h' é lead é cont 'l' 'l' 'o'

ASCII chars are one byte each; é (U+00E9) is two bytes in UTF-8 (C3 A9). Total = 6, which is what Rust's name.len() returns — not 5 (the char count) and not 10 (the UTF-16 byte count).

The fat pointer on the wire (16 bytes, x64)

offset0..88..16
fieldptrlen
value 0x000001B4_5F2C8010
(address of byte 0)		 0x00000000_00000006
(= 6)

Reading the same picture in reverse — &mut [u8]

The &mut [u8] story is identical to &DiplomatStr with three substitutions:

delta vs DiplomatStr comparison 
// Idiomatic signature
//   string                  -> Span<byte>
//
// No encoding step needed
//   Encoding.UTF8.GetBytes  -> (none)
//
// Pin the caller's Span directly
//   fixed (byte* p = bytes) -> fixed (byte* p = span)
//
// Raw struct on the wire
//   DiplomatSliceU8         -> DiplomatSliceMutU8
//   { *const u8, usize }    -> { *mut u8, usize }
example wrapper for &mut [u8] C# idiomatic 
public void FillInto(Span<byte> buf)
{
    unsafe
    {
        fixed (byte* p = buf)
        {
            Raw.Frame.FillInto(_inner, new Raw.DiplomatSliceMutU8
            {
                Ptr = p,
                Len = (nuint)buf.Length,
            });
        }
    }
}
Why this matters for IronRDP. RDP frame decoding writes into caller-owned buffers — that's exactly &mut [u8]. uniffi currently only supports immutable &[u8] (PR #2878), which means every frame would force an extra allocation + copy-back. Diplomat handles &mut [u8] natively via the same machinery as above, just with DiplomatSliceMut instead of DiplomatSlice. That's the entire technical reason we're porting to Diplomat instead of using uniffi.

Layer invariants — the contract each layer enforces

who guarantees what
/*
  Layer 1 (Rust source)
    - Lifetime of &DiplomatStr does not outlive the call.
      The borrow checker enforces this at compile time.

  Layer 2 (Macro shim)
    - From<DiplomatSlice<u8>> for &[u8] handles null-ptr-as-empty
      and reconstructs the slice via slice::from_raw_parts.
    - The macro forbids signatures that would let &DiplomatStr escape.

  Layer 3 (C ABI)
    - { ptr, len } is repr(C), 16 bytes on x64, blittable.
    - No marshalling, no allocation, no validation.

  Layer 4 (C# raw)
    - [StructLayout(Sequential)] mirrors the Rust struct field-for-field.
    - byte* and nuint match *const u8 and usize on every supported platform.

  Layer 5 (C# idiomatic)
    - Encoding.UTF8.GetBytes allocates a fresh managed byte[]
      — the caller's string is never modified.
    - fixed block guarantees the byte[] is pinned for the duration of
      the call. The pointer is valid; Rust can dereference safely.

  Layer 6 (User)
    - Just calls a normal C# method. Doesn't think about any of this.
*/

Summary — the one-line story per layer

  1. Rust source: &DiplomatStr is a Rust slice; the borrow checker controls its lifetime.
  2. Macro shim: rewrites it to DiplomatSlice<u8>, a repr(C) {ptr, len} struct.
  3. C ABI: the function takes that 16-byte struct by value — nothing else crosses.
  4. C# raw: a sequential-layout DiplomatSliceU8 mirrors the struct; the extern declares it as the param type.
  5. C# idiomatic: takes a string, encodes to UTF-8, pins with fixed, builds the struct, calls raw.
  6. User: writes Color.NameLength("héllo"). Done.
