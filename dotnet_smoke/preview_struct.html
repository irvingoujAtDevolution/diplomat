Diplomat .NET backend — Struct mapping

Stage 3: dotnet_smoke/src/lib.rs → dotnet_smoke/out/Point2D.cs + RawPoint2D.cs
What this exercises: a by-value struct (POD aggregate), public fields, a static factory, and methods that consume self by value. Contrast with opaque: the struct is the data — no handle, no destructor, no IDisposable.
dotnet_smoke/src/lib.rs Rust (input) 
#[diplomat::bridge]
pub mod ffi {
    pub struct Point2D {
        pub x: f32,
        pub y: f32,
    }

    impl Point2D {
        pub fn new(x: f32, y: f32) -> Point2D {
            Point2D { x, y }
        }

        pub fn magnitude(self) -> f32 {
            (self.x * self.x + self.y * self.y).sqrt()
        }

        pub fn translated(self, dx: f32, dy: f32) -> Point2D {
            Point2D {
                x: self.x + dx,
                y: self.y + dy,
            }
        }
    }
}
How structs differ from opaques in the bridge:
  • No #[diplomat::opaque] — fields are pub and visible across FFI.
  • No Box<Self> — passed/returned by value across the C ABI.
  • No &self / &mut self on methods — either self (by value) or static. Mutation across FFI on a value type wouldn’t round-trip cleanly.
  • The bridge macro does not emit a Point2D_destroy — nothing is heap-allocated.

using System;
using System.Runtime.InteropServices;

namespace DotnetSmoke;

internal static unsafe partial class Raw
{
    [StructLayout(LayoutKind.Sequential)]
    public partial struct Point2D
    {
        public float X;
        public float Y;

        private const string NativeLib = "dotnet_smoke";

        [DllImport(NativeLib, EntryPoint = "Point2D_new",
                   CallingConvention = CallingConvention.Cdecl)]
        public static extern Point2D New(float x, float y);

        [DllImport(NativeLib, EntryPoint = "Point2D_magnitude",
                   CallingConvention = CallingConvention.Cdecl)]
        public static extern float Magnitude(Point2D self);

        [DllImport(NativeLib, EntryPoint = "Point2D_translated",
                   CallingConvention = CallingConvention.Cdecl)]
        public static extern Point2D Translated(Point2D self, float dx, float dy);
    }
}
How struct C# differs from opaque C#:
  • C# struct, not class — value semantics, lives on the stack/inline in containers.
  • No IDisposable, no finalizer, no _inner pointer.
  • Public fields directly mirror the Rust fields. [StructLayout(Sequential)] guarantees ABI-compat with Rust’s #[repr(C)] (Diplomat enforces this on bridge structs).
  • Idiomatic struct declares the fields itself — the raw layer is just for [DllImport] declarations. Same fields, two declarations, layout-compatible.
  • No destructor — the GC reclaims the struct’s containing storage; nothing on the Rust heap to free.
